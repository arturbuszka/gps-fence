# Test CSV Data — gps-fence

Test files are generated by [`generate_test_data.py`](../generate_test_data.py).
Each file contains a synthetic GPS trajectory with a specific noise type, designed to isolate and evaluate individual filters.

To regenerate all files:
```
python generate_test_data.py
```

---

## Common parameters

| Parameter | Value |
|---|---|
| Number of points | 480 (≈ 8 h, 1 sample/min) |
| Start time | 2024-01-15 06:00:00 UTC |
| Trajectory center | 11.170°N, 15.085°E |
| Lat amplitude | ±0.003° (≈ 330 m) |
| Lon amplitude | ±0.002° (≈ 200 m) |
| Geofence | lat 11.165–11.175°, lon 15.080–15.090° |
| RNG seed | `numpy.random.default_rng(42)` — fully reproducible |

### CSV columns (Movebank format)

| Column | Type | Description |
|---|---|---|
| `timestamp` | string | `YYYY-MM-DD HH:MM:SS.000`, 1-minute intervals |
| `location-lat` | float (6 dp) | Latitude [°] |
| `location-long` | float (6 dp) | Longitude [°] |
| `ground-speed` | float (3 dp) | GPS speed [m/s], range 0.3–0.7 |

## File overview

| File | Noise type | Primarily tests | Description |
|---|---|---|---|
| `test_ideal_clean.csv` | none | — (baseline) | Pure sinusoid, zero noise |
| `test_spike_noise.csv` | impulse | **Median Filter** | 5% of points with random jump ±0.002° |
| `test_gaussian_noise.csv` | Gaussian | **Savitzky-Golay** | Continuous white noise σ=0.0002° |
| `test_drift_noise.csv` | drift | **Kalman Filter** | Accumulating random walk, detrended |

## File details

### `test_ideal_clean.csv` — Clean baseline

Pure sinusoidal trajectory with no noise. Used as a reference point: filtering should not alter the signal shape, and residuals should be near zero.

**Use:** compare with every other file; verify that enabling filters does not distort a clean signal.

---

### `test_spike_noise.csv` — Impulse noise

Base trajectory + random position jumps in 5% of samples.

| Parameter | Value |
|---|---|
| Spike fraction | 5% of samples |
| Spike amplitude | ±0.002° (≈ ±220 m) |

Impulse noise simulates momentary GPS signal loss or multipath reflections. The **Median Filter** removes it effectively without blurring edges. SG and Kalman perform poorly on this noise type.

---

### `test_gaussian_noise.csv` — Gaussian noise

Base trajectory + continuous white noise (normal distribution) on every sample.

| Parameter | Value |
|---|---|
| Standard deviation | σ = 0.0002° (≈ 22 m) |

Gaussian noise simulates typical GPS receiver error under normal conditions. **Savitzky-Golay** smooths it while preserving curve shape. Median filter has little effect on this noise type.

---

### `test_drift_noise.csv` — Drift (accumulating random error)

Base trajectory + cumulative random walk, detrended so start and end match.

| Parameter | Value |
|---|---|
| Drift step scale | 3.5 × 10⁻⁵° / sample |
| Detrending | yes — drift returns to zero at the end |

Drift simulates a slowly accumulating system error, e.g. inertial bias or ionospheric variation. The **Kalman Filter** is optimized for this type — it models drift as a stochastic process and corrects the state estimate incrementally. Best visible in the *Pipeline Steps* tab.

---

### `test_combined_noise.csv` — Mixed noise

All three noise types superimposed on the base trajectory:

| Type | Parameters |
|---|---|
| Gaussian | σ = 0.00015° |
| Impulse | 3% of samples, ±0.0015° |
| Drift | scale = 2.0 × 10⁻⁵° |

Parameters are slightly weaker than the isolated files so all three noise types remain visible simultaneously. Use to test the **full pipeline** (Median → SG → Kalman or any other order) and observe how changing filter order affects the final result.

---

### `test_breach_events.csv` — Geofence breaches

Trajectory with three deliberate exits below the geofence southern boundary (lat < 11.165°), plus continuous Gaussian noise.

| Parameter | Value |
|---|---|
| Number of breaches | 3 |
| Breach center indices | 80, 200, 360 |
| Breach duration | ≈ 20 samples (≈ 20 min) |
| Breach depth | up to 0.006° below boundary (≈ 670 m) |
| Background noise | σ = 0.00025° |

Used to verify **breach detection**: breaches are deterministic, so the expected count and timing are known. The Gaussian noise checks whether filtering hides real breaches or generates false alarms near the geofence boundary.

## How to load in the dashboard

1. Run `dashboard.py`
2. Click the **`+ CSV`** button in the top bar
3. Select a file from the `data/` directory
4. Optionally rename the dataset
5. Click **Load** — the dashboard processes the data and switches the view automatically

The loaded file appears as a new dataset in the animal selector (alongside Animal A / Animal B). To remove it, switch to that dataset and click **`×`** next to the `+ CSV` button.
